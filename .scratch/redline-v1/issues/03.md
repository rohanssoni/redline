# #3 Severity-ranked flags, each showing its verified source sentence

## What to build

After upload, the reader sees a list of **flags** — clauses capable of harming them — ranked by **severity**, each showing its exact **source sentence**.

`analyzeDocument` returns `flags[]` alongside the summary. Before any flag can reach the output, its source sentence is verified verbatim against the stored document text. A flag that fails that check is dropped — never shown with an approximate source sentence and never shown without one (ADR-0001). A flag whose source sentence cannot be shown is a bug; no code path may produce one.

Filtering and ranking:

- **Plausibility filter first** (ADR-0004): a clause is dangerous when it lets the other side change the reader's economics unilaterally after the reader is committed. A non-standard but symmetric clause (odd governing law, odd notice address) is dropped entirely, never ranked low.
- **Severity ranks consequence, not frequency** (ADR-0004): what the flag costs the reader if it fires.
- **Recall over precision** (ADR-0006): a citable clause that passed the plausibility filter is flagged even when the model's confidence that it's harmful is partial.

Flag wording in this slice is plain; hedging is a separate ticket.

## Acceptance criteria

- [ ] `analyzeDocument` returns `flags[]`, each with a severity, a plain-English explanation, and a source sentence
- [ ] Every flag's source sentence is found verbatim in the stored document text; a flag that fails this is absent from the output entirely (test with a fake model response containing a fabricated and a tidied-up source sentence)
- [ ] Flags render in severity order, each with its source sentence visible
- [ ] A fixture with a symmetric-but-unusual clause produces no flag for it
- [ ] A fixture with a partially-confident but citable dangerous clause still produces a flag
- [ ] The analysis result is persisted with the document
