# #11 Red line matches always produce a flag

Labels: ready-for-agent

## Parent

#1 — Redline v1: full-scope spec

## What to build

A clause that violates one of the reader's red lines always shows up as a flag — even when the plausibility filter (ADR-0004) or confidence threshold (ADR-0006) would otherwise drop it (ADR-0013).

Matching is semantic: a clause triggers the override when the model judges it violates the red line's intent, even if phrased nothing like how the reader wrote it (ADR-0015).

The override applies to filtering only, **never to the source-sentence check**. A red-line match whose source sentence isn't found verbatim in the document still does not render (ADR-0001, ADR-0013).

Each red-line-triggered flag is internally marked as such (with which red line it matched), so the judge and the dismissal metric can tell it apart. The reader sees it as an ordinary flag with its source sentence.

## Acceptance criteria

- [ ] `analyzeDocument` uses the reader's red lines and marks flags produced by a red-line match, recording the matched red line
- [ ] Test: a red-line match produces a flag against a fixture engineered to otherwise fail the plausibility filter
- [ ] Test: a red-line match produces a flag against a fixture engineered to otherwise fall below the confidence threshold
- [ ] Test: a red-line match whose source sentence is not in the document text does not appear in the output
- [ ] A clause phrased differently from the red line but violating its intent triggers the override
- [ ] Red-line-triggered flags get soft counter-offers like any other flag
