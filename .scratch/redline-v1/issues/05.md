# #5 Hedged flag wording only for ambiguous source sentences

Labels: ready-for-agent

## Parent

#1 — Redline v1: full-scope spec

## What to build

A flag's wording hedges ("this could allow…", "this may be read as…") only when its source sentence is itself genuinely open to more than one reading — so every hedge the reader sees is something they can check by rereading the source sentence (ADR-0007, ADR-0010).

Hedging is never used for any other uncertainty: not how a court would rule, not real-world consequences, not a general low-confidence score. Low confidence for those reasons produces a plainly-stated flag or the clause is dropped by the plausibility filter.

This requires flag generation to distinguish **textual ambiguity** from **other uncertainty** as separate signals rather than one confidence score. How that is produced (structured output fields, a separate classification pass, prompting) is the implementer's call — the spec leaves it open; record the choice.

## Acceptance criteria

- [ ] Flag output carries a signal for sentence-level ambiguity that is separate from any harm-confidence signal
- [ ] Hedged wording is applied only when the ambiguity signal is set
- [ ] Test: a fixture built around genuine sentence-level ambiguity yields hedged wording
- [ ] Test: a fixture built around a different kind of low confidence (e.g. enforceability) yields plain wording or no flag, never hedged wording
- [ ] The chosen mechanism is recorded (ADR or note on this issue)
