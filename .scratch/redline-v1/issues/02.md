# #2 Upload a document and see its plain-English summary

Labels: ready-for-agent

## Parent

#1 — Redline v1: full-scope spec

## What to build

A signed-in reader uploads a contract (PDF or Word) and sees a plain-English summary of it. The file is parsed entirely in the browser; only the extracted text is ever transmitted or stored, never the original file. The summary comes from a model call through OpenRouter.

The Next.js app itself is scaffolded by #17 (the landing page). This slice adds the layers later tickets build on: Supabase auth gating the reader's data, a document store holding extracted text plus its most recent analysis result, the OpenRouter model client behind an interface a fake can implement, and the test harness.

Decisions made while breaking down #1:

- **Test runner is Vitest** (approved dependency). Tests exercise seam contracts with a fake model client or recorded responses — no live model calls in the suite.
- **No upload-time consumer-ToS gate.** ADR-0017's exclusion is enforced by positioning and copy only; do not build a classifier.

Decisions made on 2026-09-11:

- **Trying without an account is a separate ticket, #19.** It returns the summary and ranked flags and stores nothing. This ticket covers the signed-in path.
- **Pasting text is a separate ticket, #18** (ADR-0020). Upload stays the recommended input.
- **The signed-in frame follows the app shell surface brief.**

The summary makes no claim the document text doesn't support (`CLAUDE.md` standing rule). It carries no severity and needs no source sentences — those belong to flags and gaps.

## Acceptance criteria

- [ ] A reader can sign up, sign in, and sign out via Supabase; unauthenticated visitors cannot reach stored documents or the signed-in upload
- [ ] Uploading a PDF extracts its text in the browser with pdf.js; uploading a .docx extracts its text with mammoth
- [ ] The original file never leaves the browser — only extracted text is sent to the server and stored
- [ ] Extracted text is stored per reader, and a reader can only read their own documents
- [ ] The first stage of `analyzeDocument(text, redLines)` returns a `summary`, shown to the reader after upload
- [ ] The model is called through OpenRouter via a client interface; credentials live only in `.env.local` and nothing secret is committed
- [ ] Vitest runs with a fake model client; a test covers the summary path of `analyzeDocument` without a live model call
- [ ] App deploys to Vercel
