# #7 Zero-flag rate tracking with fixed-to-rolling drift baseline

Labels: ready-for-agent

## Parent

#1 — Redline v1: full-scope spec

## What to build

The product owner can see the production zero-flag rate — the share of analyzed documents returning a clean read — compared against a baseline, so a severity filter that starts silently suppressing everything is caught (ADR-0008).

Drift comparison (numbers are given, not to be re-derived — ADR-0011, ADR-0016):

- Compare against a **fixed 20% baseline** until the switchover.
- Switchover fires at whichever comes first: **500 analyzed documents, or 90 days since launch**.
- After switchover, compare against a **rolling window**.

Both comparison logics need to exist and swap. This is a health metric, not a target to move.

## Acceptance criteria

- [ ] Every completed analysis records whether it was a clean read
- [ ] The zero-flag rate and its current baseline are viewable by the product owner (not by readers)
- [ ] Before switchover, the comparison is against a fixed 20%
- [ ] Switchover triggers at 500 analyzed documents or 90 days since launch, whichever comes first
- [ ] After switchover, the comparison uses a rolling window
- [ ] Tests cover the switchover firing on document count first and on elapsed time first
