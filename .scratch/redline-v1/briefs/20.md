## What to build
A visitor who tried a document without an account can sign up **from the result**
and keep it. The tab still holds the text and its analysis, so both are saved to
the new account's library **without calling the model again**.

That is the whole ticket: the browser submits the text and the analysis it is
already holding, and the server stores them. No re-analysis, no second model call,
no "we're just re-running it to be safe".

**The saved text must be exactly the text that was analysed**, character for
character, so every source sentence still verifies against it. If the text were
re-derived or re-normalised on the way into storage, ADR-0001's guarantee would
break silently for that one document. Verify the stored text against the flags on
save, and refuse to save a document whose flags no longer verify rather than
storing a broken one.

Once saved, the document behaves like any other in the library — reopenable,
deletable, and the signed-in features (counter-offers, question box) work on it.

If the visitor **leaves the tab before signing up, the document is gone**, because
nothing was stored. The no-account result says so plainly, before they lose it —
this is a warning that has to arrive in time to be useful, not an explanation
afterwards.

## Tests
- Signing up from a no-account result, in the same tab, saves the document text
  and its analysis to the new account's library.
- The named test: **saving on sign-up makes no model call.** Assert the stub model
  client's call count is zero across the whole save path.
- The saved text is byte-identical to the analysed text, and every source sentence
  still verifies against it after the round trip.
- Once saved, the document loads from the library like any other.
