## What to build

### 1. The model client (`lib/model/`)
- A `ModelClient` interface: one method that takes a prompt/messages plus a JSON
  schema and returns parsed, validated structured output. Narrow on purpose —
  it is the only thing tests stub.
- `createOpenRouterClient()` implementing it against OpenRouter's
  OpenAI-compatible endpoint, with the provider pin, reasoning effort and
  `response_format` the shared brief specifies. Model id comes from
  `OPENROUTER_MODEL` at call time; never a literal in code.
- It must throw a clear error when `OPENROUTER_API_KEY` or `OPENROUTER_MODEL`
  is missing, naming the variable.
- Server-only. `OPENROUTER_API_KEY` must never reach the browser bundle.

### 2. `analyzeDocument` (`lib/analysis/`)
Signature per the spec: `analyzeDocument(text, redLines, deps) → { summary, flags[], gaps[] }`,
where `deps` carries the `ModelClient` so tests inject a stub. **In this ticket
only the `summary` stage is implemented**; return `flags: []` and `gaps: []` and
leave the shape in place for #3/#4 — but do not leave a `TODO` or a stub throw:
the summary path must genuinely work end to end.

The summary makes no claim the document text doesn't support. It carries no
severity and no source sentences.

### 3. In-browser parsing
- PDF via `pdfjs-dist`, .docx via `mammoth`, both running **in the browser**.
- The original file must never be sent anywhere. Only the extracted text is
  POSTed to the server. Make that structurally true, not merely intended: the
  server route accepts text, and has no file-handling path at all.
- A scanned/image-only PDF (parsing yields effectively no text) is refused with a
  plain reason. There is no OCR.

### 4. Supabase auth + the document store
- Sign up, sign in, sign out via Supabase (`@supabase/supabase-js`, `@supabase/ssr`).
- `documents` table: id, owner (auth user), name, extracted text, analysis result
  (jsonb, nullable), created_at, updated_at. **No original file, no storage bucket.**
- Row Level Security so a reader reads and writes only their own rows. Write it
  as SQL under `supabase/migrations/0001_documents.sql`.
- An unauthenticated visitor cannot reach stored documents or the signed-in upload.
- Remember the shared brief: **the app must still start and analyse a pasted
  document with the Supabase env vars absent.** Signed-in surfaces degrade to a
  clear "sign-in isn't set up yet" state. Do not mock auth in product code.

### 5. The test harness
- `tests/support/stub-model-client.ts`: a `ModelClient` implementation built from
  a fixture sidecar. It must make no network call and need no key. It should be
  configurable enough for later tickets to drive it (e.g. hand it the payload to
  return, or build the payload from a sidecar).
- A test that covers the summary path of `analyzeDocument` with the stub — that
  the summary comes back, and that it is the one the model produced, parsed out
  of structured output. Not a "function is defined" test.

### 6. The screens
Follow `DESIGN.md` and the app shell brief exactly: Tracked Changes, white page on
canvas #C9CFD8, ink #1C1E22, crimson #B3122E only for the flag in focus, Tinos for
document text, Schibsted Grotesk for interface, change-bar gutter as the grid, no
shadows/gradients/pills/badges. Build the signed-in frame (`app/(app)/layout.tsx`),
sign-in/sign-up, the upload step, and the document view showing the summary.
States to handle: analysing; analysis failed (never shown as a clean read).

## Rules that decide whether this is done
- Read the "What does not count as done" section of the shared brief. It is
  enforced: a fixed-value function, a TODO, a not-implemented throw, or a test
  that mocks its own subject means the ticket is not done.
- **All copy a reader sees goes through the humanizer skill before you finish** —
  labels, buttons, errors, empty states, the sign-in screen. Invoke the humanizer
  skill with the Skill tool on the copy you wrote and apply what it returns.
- Use `CONTEXT.md`'s vocabulary in identifiers and copy.
- Do not add a dependency beyond the approved list. Do not commit.
