## What to build
A signed-in reader browses a saved library of their past documents and reopens
any of them to see its stored analysis — **without re-uploading and without a new
model call**. That last part is the ticket: opening a library document must not
touch the model client at all.

**Only the extracted text plus the document's most recent analysis result is
stored — never the original file.** There is no storage bucket, no file column,
no base64 blob. This is settled in `CLAUDE.md` and is a privacy promise the
product makes on the landing page, so make it structurally true.

This ticket shows whatever the stored analysis contains. Tickets that add to the
analysis (flags, gaps, counter-offers, stances) persist their own output; you
render what is there and degrade gracefully when a field a later ticket adds is
absent from an older row.

A reader can delete a document from their library. Deletion removes the text and
the analysis, not just a visibility flag — say in your report which you built and
why.

Empty library state: it should read as "nothing here yet", not as a failure, and
point at the one thing to do next.

## Tests
- The library lists the reader's past documents, most recent first, with enough to
  identify each (name, date).
- Opening a document shows its stored analysis and **makes no model call** —
  assert on the stub model client's call count being zero.
- A reader sees only their own documents (query path and the RLS policy).
- Deleting a document removes it.
- No original file exists in storage — assert the stored shape holds only
  extracted text and analysis results.
