## What to build
When a document produces no flags and no gaps above the severity threshold,
`analyzeDocument` returns an **explicit clean-read result** — not an empty array
the UI happens to render kindly. It must be distinguishable, in the type, from a
failed or incomplete analysis, so that **a failed analysis can never render as a
clean read**. That is the one thing this ticket must not get wrong: telling a
reader their contract is fine when the analysis actually broke is the worst
failure this product has.

The plain-English summary still shows on a clean read.

The UI renders a dedicated clean-read view following `DESIGN.md`, never a bare
empty list. The copy communicates confidence **without hedging**: it does not say
"we didn't find anything, but check yourself anyway". It makes no claim beyond
what the analysis supports.

Note this ticket also introduces the **severity threshold** as an explicit,
named concept rather than an implicit one, since the clean read is defined by it.
