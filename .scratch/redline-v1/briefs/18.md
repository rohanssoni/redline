## What to build
A signed-in reader can paste an agreement's text instead of uploading a file.
**Upload stays the recommended path and the one the input step leads with** — this
is a stated product decision, not a layout preference, so paste is the clearly
secondary option on the screen.

Pasted text becomes the stored document text, so it is exactly what every source
sentence is verified against (ADR-0001). The original clipboard content is never
stored in any other form.

**Both paths produce the same stored-text shape, and `analyzeDocument` does not
know which path was used.** Make that structurally true — if the analysis seam
takes an "origin" argument, this ticket is wrong.

A paste can break lines or reorder columns, so the input step says plainly that
**upload gives the most faithful source sentences**. That is the reader deciding
with the tradeoff in front of them, not a disclaimer buried in help text.

**A pasted image is refused with a plain explanation, and nothing is analysed.**
Reading it would need OCR, which is excluded on purpose — a citation is worthless
when the text it points at was misread. The refusal says that in the reader's
terms, without jargon.

## Tests
- Flags on a **pasted** fixture pass the same verbatim source-sentence check as
  flags on an uploaded one — the named test from the spec.
- Both paths produce an identical stored-text shape, and the analysis seam cannot
  tell them apart.
- Pasting an image is refused before any model call, and nothing is stored.
- Pasted text is stored as the document text, unaltered.
